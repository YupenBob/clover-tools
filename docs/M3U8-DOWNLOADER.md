# M3U8 下载器

入口：`/tools/daily/m3u8-downloader/`，支持简体、繁体、英文、韩文和日文。首页、日常工具目录、搜索索引、站点地图与语言切换均使用现有工具清单。

## 上游与实现

参考仓库：https://github.com/Momo707577045/m3u8-downloader

本次克隆存放在忽略目录 `output/upstream/m3u8-downloader`，参考提交为 `0043470a3e0be2bab156a8fea82411339f918878`。上游提供原格式和 MP4 的 StreamSaver 流式入口，但遇到空位会等待，写入没有等待磁盘背压，MP4 转换保留原时间戳。新版下载核心、解析器和界面独立实现，流式模式使用浏览器原生文件写入，没有引入其 Vue、StreamSaver、远程脚本或页面注入代码，也没有改变上游仓库。

新增模块：

- `config/hls.mjs`：统一配置核心版本、分片大小、下载默认值、并发 / 超时 / 重试边界、导出内存上限、缓存名称、Worker 时限和 UI 更新频率。

- `src/lib/hls/playlist.ts`：HLS 解析、序号 IV、媒体身份摘要、ffconcat 清单与重新封装参数。
- `src/lib/hls/downloader.ts`：有限并发、请求与响应体超时、指数退避、取消、范围验证、AES-CBC 解密和媒体响应检查。
- `src/lib/hls/cache.ts`：IndexedDB 分片缓存；成功写入事务后才标记完成，存储错误会停止任务。
- `src/lib/hls/remux.ts` / `src/scripts/hls-remux.worker.ts`：按需加载的本地 FFmpeg Worker、逐片探测、流复制导出及可中断的封装。
- `src/lib/hls/stream.ts` / `src/lib/hls/file.ts`：有限预取、写入背压、逐片封装、原生文件选择 / 写入 / 部分提交。保存接口与下载和封装解耦。
- `src/lib/hls/timeline.ts`：TS 的 PTS / DTS / PCR、连续计数，以及 fMP4 的初始化头、全局分片序号、解码时钟和最终时长。编码参数集比较忽略合法填充字节，但保留真实编码结构检查。
- `src/components/M3u8Downloader.astro` / `src/scripts/m3u8-downloader.ts`：五语共用界面、分片分页、状态图、进度、缓存恢复、范围选择、缺失报告和本地预览。

## 缺口处理

1. `EXT-X-GAP` 不发请求；404 / 410 立即跳过，其他分片故障在配置次数内重试，完成后标记跳过。
2. 队列不会被缺失分片卡住。缓存按媒体列表内容的 SHA-256 摘要和原分片索引保存，因此完成顺序不会影响导出顺序。
3. AES 密钥错误、初始化片段不可用、解密错误和存储失败视为任务故障，暂停任务，不把整条视频静默标记成缺失。密钥与初始化请求的临时故障有限重试，404 / 410 直接暂停。
4. 导出从缓存按原顺序取回成功分片；fMP4 为每个分片补上其对应初始化数据。FFprobe 检查流，无法识别的媒体被跳过并记录。
5. FFmpeg concat demuxer 将每个保留分片的时间戳接到前一个分片后，使用 `EXTINF` 时长，不加入缺失分片的时长。`-c copy` 不重新编码，`-avoid_negative_ts make_zero` 统一输出起点；MP4 加 `faststart`，TS 重发流头。
6. 页面与 JSON 报告显示缺口数量、原时间范围、HTTP / 校验错误、序号及请求次数。报告包含资源 URL，应在分享前检查其中的令牌。

缺失画面无法恢复。若分片不是独立可解码的，缺口后的部分帧可能依赖丢失帧，要到下一个关键帧才能正常显示。编码类型 / 流结构变化、下载成功但内部已损坏的码流也不保证可接续。重新封装不等于重建这些内容。

## 支持与边界

支持主播放列表的清晰度选择、相对地址及重定向后的地址基准、普通 TS、AAC、fMP4 的 `EXT-X-MAP`、显式及隐式字节范围、标准 AES-128、显式 IV、媒体序号默认 IV、密钥轮换、`METHOD=NONE`、`EXT-X-DISCONTINUITY` 与直播快照。

暂不支持独立外置音轨、字幕合并、SAMPLE-AES / DRM、变量替换、持续直播录制。选择标记有独立音轨的清晰度时会明确拒绝，防止导出无声视频。资源源站需允许 CORS；浏览器无法伪造 `Referer` / `Origin` 或绕过网站访问控制。发送登录 Cookie 仍受跨站 Cookie 和服务器授权策略限制。

缓存包含解密后的媒体，在当前浏览器保存，不上传 CloverTools。密钥仅在任务内存中保存。普通模式刷新后重新解析相同列表与范围可复用缓存；流式模式可直接恢复持久化任务快照。清理浏览器站点数据或点击清除任务缓存会删除相应媒体。播放列表变化会产生不同缓存身份，避免把不同时期的列表混用。

普通模式可选择 MP4 / TS，单次选中媒体导出上限 384 MiB，手机和内存不足的浏览器可能更低。下载分片存放在 IndexedDB，但普通封装的 WASM 文件系统和输出仍需要整文件内存；取消封装会终止 Worker，下载缓存仍可继续使用。

## 特大视频：边下载边保存

开启特大模式后可选原格式 / MP4，默认原格式。先点击“准备流式保存”识别首个可用分片的封装与编码，再点击“选择文件并开始”选择文件。文件选择器和恢复权限请求必须直接由点击触发，避免浏览器丢失用户操作授权。原格式自动使用 TS / MP4 / AAC 扩展名；MP4 输出为 fragmented MP4，部分较老播放器不支持，可使用普通 MP4 导出或兼容播放器。

流式模式通过安全上下文中的 `showSaveFilePicker` 能力检测启用，优先支持 Chrome / Edge；不支持的浏览器保留普通导出。未使用 StreamSaver、隐藏 iframe 或服务端代理，不需要扩大现有 CSP。

下载仍复用原解析、有限重试、字节范围及 AES-128 解密逻辑。下载任务的 `DownloadFlow` 按原顺序消费终态结果，缺失片段立即推进；磁盘写入完成后才推进消费位置，最多预取配置窗口中的分片。源分片持久保存到 IndexedDB，只有当前分片进入 Worker。TS / AAC 原格式保存保留媒体载荷；MP4 每片使用 `-c copy` 生成自包含的 moof / mdat，统一全局时钟后只写一次初始化数据，丢弃临时文件中的局部索引和编辑列表。完成或部分提交时只回写小型初始化头中的最终时长。

时间轴以源音视频 DTS 的共同起点为基准，按已保留分片时长接续；不计入缺失时长，保留音视频相对偏移。`EXT-X-DISCONTINUITY` 重建该组的源时钟基准，TS 处理 33 位时钟回绕。编码参数、流结构或无法接续的时间轴变化会停止追加并保留缓存，不把这种系统性问题当作缺片。

流式模式不受整文件 384 MiB 上限限制。`config/hls.mjs` 配置单片上限（默认 64 MiB）、额外响应缓冲预算（128 MiB）、预取窗口（6 片）、Worker 回收间隔（128 片）和堆回收阈值（384 MiB）。实际下载并发根据缓冲预算和单片预留收紧；响应体逐块检查大小，缺少 Content-Length 也能执行上限。每片处理后删除 Worker 临时文件，并按策略回收 Worker。总视频大小不会作为一个 ArrayBuffer / Blob 读入页面，任务索引与报告元数据仍随分片数量增长。

### 暂停、部分保存与刷新恢复

- 页面内暂停等待当前完整分片写入后停下，保留写入流，继续时从当前位置追加。“保存当前部分”提交已完成的完整分片；之后继续会从缓存重建输出。
- 浏览器文件写入通常使用临时文件，关闭流才提交最终文件。刷新 / 关闭页面会终止当前写入流，不能依赖异步页面退出事件提交文件。
- 页面显示“恢复上次流式任务”。恢复使用持久化的播放列表快照、所选范围、格式、下载设置、缺失状态和文件句柄；不必重新获取可能已过期的播放列表。文件写入前重新请求授权，从缓存顺序重建输出，再继续未完成下载，不重复下载已成功缓存的分片。
- 已写过的缺口重新下载成功后也从缓存重建文件，避免把补回的片段错误追加在尾部。缓存错误、密钥错误、写入权限丢失、磁盘写入失败及封装故障都会暂停，不删除已缓存媒体。
- IndexedDB 保留数据库名 `clover-hls-v1`，版本升级到 2：原 `chunks` 仓库不变，新增 `tasks` 存储任务快照及分片终态。其他新版本页面在版本变化时关闭连接；旧页面阻止升级时提示关闭其他下载页面。

恢复需要额外磁盘空间：源分片缓存、浏览器写入临时文件和输出文件可能同时存在，仍受浏览器缓存配额限制。“清除任务缓存”同时删除该任务的分片、状态和活动快照，不会删除已保存到用户文件系统的文件。媒体和文件句柄仅保存在当前浏览器，不上传；AES 密钥不持久保存。

## 引擎构建与部署

开发执行 `npm run dev`，`predev` 自动运行 `prepare:hls`；构建执行 `npm run build`，同样准备引擎。`@ffmpeg/core` 固定为 `0.12.10`，单线程，运行不要求跨源隔离。

`scripts/prepare-hls-core.mjs` 将约 30.7 MiB 的 WASM 分为 4 个不超过 8 MiB 的文件，并生成带 SHA-256 的清单，避免 Cloudflare Pages 单文件 25 MiB 限制。文件在 `public/vendor/ffmpeg/0.12.10/`，作为可重建产物忽略，构建时进入 `dist`。浏览器在导出或流式准备时同源加载、校验、拼合与实例化引擎，无第三方 CDN 依赖。

`public/_headers` 的 CSP 允许 `wasm-unsafe-eval`、同源 Worker 和 `blob:` 媒体预览。版本化引擎资源使用长期不可变缓存。首次导出或流式准备需下载约 31 MiB，后续可使用浏览器 HTTP 缓存。

FFmpeg 核心依赖使用 GPL-2.0-or-later；许可证和对应源码 / 构建说明见 `public/vendor/ffmpeg/NOTICE.md`。本次工作只修改本地代码，没有发布站点。
