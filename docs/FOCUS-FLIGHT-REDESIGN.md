# 专注航班重做计划

日期：2026-10-05。状态：按用户 SVG 要求完成实现，验收证据见 [QUALITY.md](QUALITY.md)。最终实现见 [FOCUS-FLIGHT.md](FOCUS-FLIGHT.md)。

2026-10-06 体验修订：用户反馈视觉元素过多。巡航改为场景优先，整套界面闲置后隐去，轻触、底部入口或键盘唤回；唤回时的时间缩小到角落，光线与声音归入同一个设置面板，任务保留在票面。暂停和键盘操作保持控件可见，抵达仅突出留念主票。下文保留初次重做的调研与计划，当前行为以实现说明为准。

实施约束更新：用户要求使用 SVG，替代生成图片。舷窗、机翼、云层、机票与航图使用可维护的 SVG；地图轮廓继续来自真实地理数据。此前关于影像背景与 Three.js 场景的方案由 SVG 分层、滤镜、光照和镜头变换替代，不接入生成图片。

目标：让用户完成一次有起点、有过程、有抵达感的专注旅行。重点是可信的地理画面、明确的登机仪式、舒服的巡航环境和有记忆点的落地反馈。

建议方向：**半写实航空客舱 + 真实地理航图 + 连贯的飞行流程**。用一次撕下机票副票的动作进入专注，用一次抵达收回注意力；让长时间停留的画面和声音保持舒适。

用户明确要求：**登机必须模拟撕下机票副票**。撕票是正式登机的核心交互，需要可操作的主票、副票与纸张分离过程；快捷操作和无障碍操作也保留副票分离反馈。

**现有实现的问题**

1. `FocusFlight.astro` 用少量手写顶点拼出海岸线。岛屿、半岛和沿海形状失真，固定地区示意图的细节经不起观看。
2. `routeGeometry()` 采用屏幕上的二次曲线；航线、飞机朝向与真实球面几何没有建立关系。
3. 提交表单后直接创建计时会话，缺少检票、登机和起飞之间的视觉、声音反馈。
4. 沉浸视图将同一套地图、票面和声音设置铺满屏幕，准备操作仍占据主要画面。
5. 声音是一层合成噪音，缺少阶段、远近和起伏；落地反馈主要由状态文字和下载按钮承担。
6. 当前回归检查主要证明计时、恢复、下载和兼容性正确。新版还需要实际审看动效、构图和声音。

**完整的用户旅程**

| 阶段 | 用户看到、听到与操作的内容 | 转场与计时约定 |
| --- | --- | --- |
| 候机 | 目的地、真实区域航图、可填写的纸质登机牌；选择任务、时长和声音偏好 | 配置阶段不计时；地图准备完成前也能填写和登机 |
| 撕票登机 | 拖动机票副票，沿齿孔逐步撕开；副票撕断离开，主票留下撕口与登机章 | 鼠标、触摸可直接撕票；单击和 Enter 触发同一分离过程；副票完整撕下时创建唯一会话并开始计时 |
| 起飞 | 客舱画面接管屏幕，舷窗外视角逐渐升高，穿过薄云；启用声音时发动机声渐入 | 首次完整过场目标 4–6 秒；属于已选择的专注时间，可跳过；短航程自动缩短 |
| 巡航 | 舷窗、机翼、云层与柔和光照；可切换到真实航图，观察位置、航程和预计抵达 | 主体保持缓慢、稳定；进入巡航后配置表单收起，只有任务、时间和少量控制 |
| 下降与抵达 | 临近结束时场景和声音缓慢变化；到时出现目的地与抵达反馈 | 由有效专注进度推导阶段；落地记录仍以实际计时截止时间为准 |
| 旅程留念 | 已盖章登机牌、城市到访章、完成的航线、专注时长与任务；保存纪念卡或开始下一程 | 完整完成才入日志；刷新不重复盖章或累计记录 |

撕票由用户掌握节奏，分离过场约 0.76 秒，起飞最多 6 秒，可直接进入巡航。快捷操作仍呈现副票分离；减少动态效果时降低纸张旋转和转场幅度，保留撕断反馈。长过场不能成为开始工作的负担。

**必须实现的撕副票仪式**

- 票面由一张主票和一张可撕副票构成，中间有真实可见的齿孔线。主票包含航线、任务、时长和座位，副票保留相应航班与座位信息，完整地属于同一张机票。
- 桌面副票在右侧，向外拖动；手机副票在下方，向下撕开。副票有明确的可抓取边缘和简短提示，拖动区域与表单操作分开。
- 拖动中，主票保持固定，副票随手指或鼠标偏移、轻微弯折、翘起和旋转。连接处逐段断开，纸张背面、阴影、毛边和少量纸纤维随撕裂进度显露。
- 用可感知的阻力、齿孔逐段断开的反馈与最终撕断动作形成节奏。启用声音时配合轻微纸张拉扯、撕裂声和短促登机提示；声音跟随实际撕票进度。
- 松手未达到完整撕断条件时副票回弹并复位，继续停留候机，不创建计时会话。拖动中取消、失焦或刷新，也不会误开始航程。
- 完整撕下后副票沿拖动方向离开，主票保留不规则撕口，盖上已登机章，再切入客舱和起飞。主票作为这次旅程的纪念票，落地时补上抵达章。
- 完整撕断是唯一的登机提交点。连续点击、重复释放或多标签同步不能创建重复会话；计时和完成记录不依赖动画播放结束。
- 为键盘和不便拖动的用户提供「撕下副票并登机」按钮，Enter／Space 激活后呈现同样的副票分离与主票盖章；减少动态时用简短分离反馈完成操作。
- 手势捕获只限副票区域，页面其他位置仍可正常滚动。竖屏和横屏切换时保留清楚的票面，取消尚未完成的手势。
- 实际录屏必须能看到完整票面、抓取副票、齿孔撕裂、彻底分离、主票留存和进入客舱的连续过程。

**地图重做**

- 海岸线与陆地区域采用 [Natural Earth 1:10m 地理数据](https://www.naturalearthdata.com/downloads/10m-physical-vectors/)，湖泊与自然地形区域也采用其矢量数据。数据裁剪、保留拓扑的简化与 SVG 路径生成在准备资源时完成，保持岛屿和主要沿海轮廓；以实际显示尺度决定细节。
- 机场位置取自 [OurAirports 开放数据](https://ourairports.com/data/)，按机场代码校验。现有六条航线先完成逐条地理审看，再扩展目的地。
- 航线使用机场经纬度之间的大圆插值，飞机方向跟随航线切线。大圆是虚拟航程的地理路径，不表示真实航空公司的实际飞行轨迹；专注分钟和航线距离分别表达。
- 采用横纵等比例的 Mercator 投影、真实海岸线、海洋与自然地形区域纹理。昼间、黄昏、夜航由 SVG 舷窗光照表达；航图位置与地理形状保持一致。氛围是视觉设定。
- 航图提供「跟随」与「全程」两个明确视角。默认取景让当前航线和地理细节占据有效画面，飞机运动平滑；切换航线时完成缓慢的镜头过渡。
- 六条亚洲路线使用裁剪后的区域 SVG，初始 HTML 已包含矢量轮廓，无外部地图请求和加载等待。记录原始来源、版本、处理方式与文件哈希。
- [Natural Earth 使用条款](https://www.naturalearthdata.com/about/terms-of-use/)与 OurAirports 数据页明确提供公共领域数据。最终素材说明仍保留来源，便于维护和复核。

**客舱与界面**

- 候机界面采用暖灰、香槟和纸张质感；巡航切换为深靛蓝客舱与窗外自然光。用空间、材质和明暗建立层次。
- 舷窗有可信的厚度、内框、柔和反光与机翼透视。云层缓慢移动，光照随所选昼夜氛围改变；舷窗、机翼、云层与纸张用原创 SVG 绘制，外部地理数据逐项保留许可记录。
- 「舷窗」和「航图」是同一航程的两种观察方式，共用位置、阶段、光照和进度。巡航默认舷窗，航图可一键切换；准备时用航图帮助选择目的地。
- 桌面让场景成为主要画面，任务与航线信息置于边缘；手机以纵向舷窗为主，底部控制照顾拇指和安全区域，横屏可展开宽幅场景。
- 巡航控制只保留暂停／续航、声音、视角和退出。交互停止后辅助控件淡出；鼠标移动、触摸或键盘聚焦会唤回。暂停、退出等必要操作始终可通过键盘到达。
- 表单、日志、相关工具与站点导航退出飞行场景。退出沉浸后恢复原滚动位置、键盘焦点与准备界面状态。
- 全屏属于可选增强；在普通页面中同样提供完整客舱体验。

**声音与仪式反馈**

- 登机前明确提供「有声登机」和「安静登机」。声音从用户操作后启用，保留即时静音和音量控制。
- 客舱声场分为低频发动机、柔和气流和少量环境底声；本轮采用原创本地合成，不接入外部录音；独立控制引擎和气流，检查循环接缝与长时间舒适度。
- 撕票使用与拖动进度同步的纸张拉扯和撕裂音效；登机和抵达使用短促、克制的提示音。起飞和下降用平缓的音量、频谱与空间变化，巡航保持稳定。
- 阶段提示配五语字幕，不强制播报；登机和落地使用原创轻声提示。
- 所有音轨淡入、淡出和交叉混音，避免响度突然增加。暂停时减弱或停止环境声，续航平滑恢复；用户可选择安静运行。
- 声音失败、音频授权被拒绝、后台冻结等情况不影响计时；重新打开页面不自动重播登机或落地声音。

**落地与记忆**

- 抵达先给一个简短的场景反馈，再呈现保留撕口与登机章的主票，并补上抵达章。展示目的地、真实航线距离、有效专注时长、任务与抵达时间。
- PNG 纪念卡采用同一套票面、地图与盖章视觉，五种语言和长任务都经过实际导出审看。
- 飞行日志呈现按日期排列的票面与到访城市，提供完成航线回顾。统计明确以保存的完成记录为基础；若后续加入累计里程，需独立持久化与迁移，不能把最近 20 条当成全部历史。
- 退出或提前结束保留现有确认行为；已经完成的记录不会被撤销。清除日志后刷新，也不会重新生成旧票面和旧记录。

**实现结构**

- 保留 Astro 的五语薄路由和共享组件，以独立 `flow` 组合承载此工具。飞行场景单独组织，按 `focus-flight` 范围隔离样式。
- 使用独立 SVG 客舱、航图与纸张组件，CSS 控制光线和材质；地理 SVG 以 CSS 位移合成镜头，动态航线 SVG 以 viewBox 同步取景，避免飞机移动重绘海岸线。没有 WebGL 或位图依赖，初始 HTML 已能显示真实航图。
- 地理预处理与运行时使用同一投影公式；逐条审看沿海、机场、标签与航线取景，使用球面插值计算飞行位置。
- 保留 `focus-flight.ts` 的截止时间、暂停恢复、完成去重逻辑；新建独立的地理几何、飞行阶段、视觉场景、撕副票交互和声音模块。
- 计时状态与视觉阶段分离。阶段从有效进度推导，动画完成事件不控制计时或完成记录。后台恢复直接校准到当前阶段，暂停冻结有效进度。
- 继续读取现有 v1 会话和日志。新增声音混音、光线与地图镜头偏好独立保存，环境声不会自动重播；迁移与跨标签同步明确处理旧会话、完成和清除情况。
- 场景仅在可见且需要变化时渲染；SVG 航图镜头与飞机最多每秒更新约 30 次，静止时停止帧循环；切换航图时暂停客舱云层动画，隐藏页面停止视觉帧循环。
- 网页可控制自身画面和声音、尝试保持屏幕唤醒。系统级通知屏蔽与其他 App 限制不属于浏览器能力，产品文案保持准确。

**实施顺序与阶段交付**

| 顺序 | 工作 | 可审看的交付物 | 进入下一步的标准 |
| --- | --- | --- | --- |

| 3 | 声场、留念与五语 | 跟随手势的撕票声音和阶段声音、保留撕口的落地主票、城市章、PNG、日志；五语完整文案 | 声音无明显接缝和突增；落地反馈与计时完成一致；实际卡片清晰可读 |

这些阶段组成同一轮完整改版。第一阶段直接决定地图和客舱的最终质量，必须完成真实数据的可运行样机和人工审看。

**验收标准**

1. 地理：六条航线的机场、陆海轮廓、终点与朝向正确；切换航线时镜头不跳变。几何反例覆盖跨日期变更线、同点、接近对跖点和无效输入。
2. 仪式：必须实际模拟撕下机票副票，并呈现齿孔逐段撕裂、纸张弯折和主副票分离。验证未撕断回弹、完整撕断开始、取消手势不开始、重复输入不重复登机；鼠标、触摸、键盘和减少动态均保留分离反馈。录屏呈现撕票、起飞、巡航到抵达的完整旅程。
3. 巡航：默认画面适合长时间停留，控件唤回和键盘访问顺畅；声音无循环断点、忽大忽小或强制播放。
4. 计时：在起飞、下降、暂停、后台、刷新、跨语言和多标签情况下保持同一截止时间；仪式不能重复创建或重复完成会话。
5. 兼容：360／390／768／1440px、手机横竖屏、深浅主题与五语均审看；SVG 无须 WebGL；音频拒绝、存储拒绝、全屏拒绝和减少动态都有可用体验。
6. 性能目标：候机与细节由 HTML／SVG 同时显示，无需等待外部地图。云层使用 CSS 动画，航图更新上限约 30fps；对桌面、手机与 CPU 降速环境实测帧耗时。记录测试设备、网络／CPU条件、资源字节、首个可操作时间和帧耗时，以实测结果调整质量档位。
