# CloverTools 推进策略

更新：2026-10-01。

## 当前判断

项目已有 71 个工具、五语访问能力与独立 CSDN 发布包。本轮接续工作区已有的指南、政策页和分阶段收录工作，优先把「搜索发现 → 理解场景 → 实际使用」连起来。下一阶段的工具和语言投入，依据实际数据排序。

目前没有可用的 GSC、站点访问或广告收入数据快照，因此不把页面数量当作增长效果。本轮建立的是可验证的内容与发布基础。

## 本轮落地

| 工作 | 结果 | 验收方式 |
| --- | --- | --- |
| 场景内容 | 16 篇站内指南、20 份工具深度说明，包含步骤、示例、边界与 FAQ | 内容关联检查、JSON 示例实际输出检查 |
| 内容可信度 | 指南展示参考来源，发布与更新日期分开维护 | 静态内容与 Article 结构检查 |
| 用户信任 | 五语隐私、条款与联系页；明确 IP/HTTP 网络请求与语言/主题存储 | 15 个政策页访问测试 |
| 国际化 | 统一内部语言 ID、公开前缀与页面可用范围；无翻译的指南保持可读 | 首次识别、手动切换、查询参数保留测试 |
| 收录策略 | 延续原有设置：简体工具先收录，其他语言工具先保留访问能力 | sitemap、robots、canonical、hreflang 一致性检查 |
| 发布质量 | 现有 build 命令自动执行检查，GitHub Actions 增加浏览器回归 | `npm run check:all` 与 `npm run check:browser` |

指南目前只有简体版本；其他语言首页可访问这些指南，手动切换语言时进入该语言首页。`hreflang` 只描述真实存在且允许收录的内容版本。规则依据：[Google 多语言页面说明](https://developers.google.com/search/docs/specialty/international/localized-versions)。sitemap 只包含允许收录的规范页面，依据：[Google sitemap 说明](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)。这些检查不保证搜索引擎收录或排名。

## 后续推进顺序

本次依据用户明确提出的 CS2/瓦洛兰特练枪需求，新增第一人称 FPS 练枪工具。以七种训练场景、四把步枪、鼠标校准和具体训练指标承接使用需求，复用现有五语入口与本地处理约定。参数来源、近似还原边界和验收见 [FPS-AIM-TRAINER.md](FPS-AIM-TRAINER.md)。新增工具使深度说明增至 21 份；这不代表已证明回访或流量增长，后续仍需真实使用反馈与访问数据。

| 优先级 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 | 建立搜索与访问基线 | 保存最近 28 天按页面/查询拆分的曝光、点击、CTR、收录状态及访问数据；记录观察窗口 |
| P1 | 优化已有入口 | 从有曝光但点击不足、用户反复找不到结果的场景选小批页面；一次只改一个可观察问题，保留前后对比 |
| P1 | 校验语言版本 | 按工具检查界面语言、合法输入、错误输入、复制/下载、移动端与描述；通过后在共享配置开放对应语言收录 |
| P2 | 验证再次使用需求 | 先依据反馈和访问数据确认需求，再考虑收藏、最近使用或场景入口；任何使用指标只记录事件和工具标识，不记录输入内容 |
| P2 | 评估广告体验 | 在真实流量与广告数据可用后比较广告收益、布局占位与操作完成情况；政策页保持无广告 |
| P3 | 新工具与新渠道 | 仅在现有工具不能覆盖已证实需求时新增；每项附用户场景、实现成本和验收依据 |

多语收录按当前配置以语言为单位开放。若后续只校验了部分工具，应先扩展到「语言 + 工具」的审核名单，再逐项开放，不能把部分审核结果视为整种语言已通过。

## 每周复盘记录

用相同窗口保存数据与结论，维护以下字段：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| 页面/查询、曝光、点击、CTR、平均位置 | Search Console | 判断用户正在搜索什么，以及入口是否匹配 |
| 可收录页数、实际收录页数、抓取问题 | 构建检查 + Search Console | 区分技术故障与内容问题 |
| 工具访问、回访、设备分布 | 已配置的站点统计 | 判断使用场景与移动端问题 |
| 可复现错误、修复日期、验证方式 | GitHub Issues / 本地验证 | 保持可靠性与文档同步 |
| 广告数据（如已启用） | 广告后台 | 衡量真实收益与体验代价 |

页面浏览量不能代表工具操作成功；操作成功率需要另行设计仅含事件标识的统计，并完成隐私说明后再接入。

## 执行约束

配置入口与发布验证见 [QUALITY.md](QUALITY.md)。每轮任务完成实现、必要验证与文档更新后提交并推送远程；只有部署状态确认后才报告上线成功。需要决策时集中编号，说明背景、问题及影响。
