# 数据库索引原理是什么？B+树与索引优化完全指南

> 数据库索引是提升查询性能的关键，但滥用索引反而拖累写入性能。本文从B+树原理出发，讲解索引结构、复合索引、最左前缀原则，以及索引失效的常见场景。

## 为什么需要索引

没有索引时，查询需要全表扫描（O(n)）；有了索引，只需几次磁盘IO就能定位数据（O(log n)）。

## B+树结构

MySQL默认索引结构是非叶子节点存key，叶子节点存数据（InnoDB）。所有叶子节点在同一层，查询效率稳定。

## 创建索引

```
-- 单列索引
CREATE INDEX idx_name ON users(name);

-- 复合索引（最左前缀）
CREATE INDEX idx_age_name ON users(age, name);

-- 唯一索引
CREATE UNIQUE INDEX idx_email ON users(email);
```

## 最左前缀原则

```
-- 复合索引 idx(age, name, city)
-- 能命中的查询：
WHERE age = 20
WHERE age = 20 AND name = 'Tom'
WHERE age = 20 AND name = 'Tom' AND city = 'BJ'

-- 不能命中（跳过age）：
WHERE name = 'Tom'
WHERE city = 'BJ'
```

## 索引失效场景

```
-- 1. 函数/计算
WHERE YEAR(created_at) = 2024

-- 2. 类型转换
WHERE phone = 13800138000  -- phone是varchar

-- 3. OR导致全表
WHERE name = 'Tom' OR age = 20  -- age无索引
```
