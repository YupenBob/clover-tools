## 请求超时怎么处理？前端与Node.js超时处理完整指南

网络请求超时是分布式系统中不可避免的问题。以下是系统化的超时处理方案。

## 前端fetch的超时处理

```javascript
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 5000);

fetch('/api/data', { signal: controller.signal })
  .then(r => {
    clearTimeout(timeoutId);
    return r.json();
  })
  .catch(err => {
    if (err.name === 'AbortError') {
      console.log('请求超时，已取消');
    }
  });
```

## 封装带超时的fetch函数

```javascript
async function fetchWithTimeout(url, options = {}) {
  const { timeout = 10000, ...fetchOptions } = options;
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), timeout);

  try {
    const response = await fetch(url, { ...fetchOptions, signal: controller.signal });
    clearTimeout(timeoutId);
    return response;
  } catch (error) {
    clearTimeout(timeoutId);
    if (error.name === 'AbortError') {
      throw new Error(`请求超时（${timeout}ms）: ${url}`);
    }
    throw error;
  }
}
```

## 请求重试与超时结合

```javascript
async function fetchWithRetry(url, options = {}) {
  const { retries = 3, timeout = 5000 } = options;

  for (let i = 0; i < retries; i++) {
    try {
      return await fetchWithTimeout(url, { timeout });
    } catch (error) {
      if (i === retries - 1) throw error;
      console.log(`请求失败，${i+1}/${retries}，等待重试...`);
      await new Promise(r => setTimeout(r, 1000 * (i + 1)));
    }
  }
}
```

## 超时策略设计建议

- 不同类型请求设置不同超时：数据获取10s、文件上传60s+
- 超时后给用户明确提示
- 重试前使用退避策略
- 关键操作（如支付）超时后需确认服务端状态

## 常见问题 FAQ

Q: 超时后服务器还在处理请求，会重复提交吗？
A: 会的。关键操作需要服务端实现幂等Token机制。

Q: WebSocket连接适合设置超时吗？
A: 不适合。WebSocket是长连接，应该使用心跳机制检测连接是否存活。
