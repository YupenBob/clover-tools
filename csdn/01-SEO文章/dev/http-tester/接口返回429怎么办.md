## 接口返回429怎么办？Rate Limit处理完整指南

HTTP 429是"Too Many Requests"状态码，表示在规定的时间内发送了过多请求。这是服务端在保护自身资源不被耗尽时的防御性响应。

## 429错误的典型特征

- 状态码：429 Too Many Requests
- 响应头通常包含：Retry-After: 3600（需要等待的秒数）
- X-RateLimit-Remaining: 0（剩余请求次数）

## 如何正确处理429

```javascript
// 指数退避重试（Exponential Backoff）
async function fetchWithRetry(url, options = {}, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const response = await fetch(url, options);

    if (response.status === 429) {
      const retryAfter = response.headers.get('Retry-After');
      const delay = retryAfter
        ? parseInt(retryAfter) * 1000
        : Math.pow(2, attempt) * 1000 + Math.random() * 1000;

      console.log(`429 Too Many Requests，等待 ${delay}ms后重试...`);
      await new Promise(r => setTimeout(r, delay));
      continue;
    }
    return response;
  }
  throw new Error(`超过最大重试次数 ${maxRetries}`);
}
```

## 请求队列与并发控制

```javascript
class RateLimitedQueue {
  constructor(maxConcurrent = 5, requestsPerSecond = 10) {
    this.maxConcurrent = maxConcurrent;
    this.requestInterval = 1000 / requestsPerSecond;
    this.running = 0;
  }

  async add(fetchFn) {
    return new Promise((resolve, reject) => {
      if (this.running >= this.maxConcurrent) {
        setTimeout(() => this.add(fetchFn), 100);
        return;
      }
      this.running++;
      fetchFn().then(resolve).catch(reject).finally(() => {
        this.running--;
        setTimeout(() => this.process(), this.requestInterval);
      });
    });
  }
}
```

## 预防措施

- 在API文档中明确查找Rate Limit规则
- 实现请求节流（Throttling），避免短时间发送大量请求
- 缓存频繁请求的数据，减少不必要的API调用

## 常见问题 FAQ

Q: 429和5xx服务器错误有什么区别？
A: 429是客户端请求过多，责任在调用方；5xx是服务端自身问题，责任在提供方。

Q: 如果没有Retry-After头，应该等多久？
A: 使用指数退避策略：第1次等1秒，第2次等2秒，第3次等4秒。
