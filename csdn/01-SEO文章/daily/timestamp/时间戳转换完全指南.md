## Unix时间戳转换完全指南

时间戳是后端开发中最常用的时间表示方式，但10位（秒级）和13位（毫秒级）的混用是新手最常踩的坑。

## 10位 vs 13位

```javascript
// 10位：秒级，从1970年起的秒数
const ts10 = 1715299200;

// 13位：毫秒级，从1970年起的毫秒数
const ts13 = 1715299200000;

// 时间戳位数快速判断
function getTsType(ts) {
  return Number(ts) > 1e12 ? '毫秒级（13位）' : '秒级（10位）';
}
```

## JavaScript中的转换

```javascript
// Date对象 → 时间戳
const ms = new Date().getTime();
const sec = Math.floor(ms / 1000);

// 时间戳 → Date对象
const dateFromMs = new Date(1715299200000);
const dateFromSec = new Date(1715299200 * 1000);
```

## Python中的转换

```
from datetime import datetime, timezone

# Date对象 → 时间戳
dt = datetime(2024, 5, 10, 0, 0, 0, tzinfo=timezone.utc)
ts_sec = int(dt.timestamp())

# 时间戳 → Date对象
dt = datetime.fromtimestamp(ts_sec, tz=timezone.utc)
```

## 常见问题 FAQ

Q: 为什么后端返回的时间戳是10位，前端需要×1000？
A: JavaScript的Date.getTime()返回毫秒级，大多数后端习惯用秒级。

Q: 2038年后10位时间戳会溢出吗？
A: 会的。2^31-1秒 = 2038-01-19 03:14:07。新项目应使用毫秒级。
