# Git合并冲突怎么解决？3种场景下的冲突处理完整指南

> Git合并冲突是团队协作中最常见的问题之一。本文详解3种场景下的冲突处理：本地分支合并、rebase冲突、多人同时修改同一文件。

## Git冲突的本质

冲突只发生在同一个文件的同一个位置被两个分支同时修改时。Git不知道该留哪个，所以把选择权交给你。

## 解决冲突的5个步骤

```
1. git status  # 确认哪些文件冲突
2. 打开冲突文件，找到 <<<<<<< HEAD ... ======= ... >>>> 标记
3. 编辑文件，决定保留哪部分（或合并两者）
4. git add <file>  # 标记为已解决
5. git commit  # 完成合并
```

## 3种场景

### 1. 两个分支修改了不同位置

Git自动合并，只需commit即可。

### 2. 同一位置修改了不同内容

手动选择：保留ours、保留theirs、或重新写一个。

### 3. 同一位置同一行被不同人修改

最复杂的情况，需要沟通后决定最终内容。

## Abort冲突合并

```bash
git merge --abort  # 放弃合并，回到合并前状态
git rebase --abort  # 放弃rebase
```
